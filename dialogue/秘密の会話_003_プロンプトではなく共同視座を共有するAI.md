# 秘密の会話 003｜プロンプトではなく、共同視座を共有するAI

タグ: #意識の次元マッピング #AI共創 #共同視座 #共同観測 #SharedViewpoint #CoObservation #未来観測 #未実装構想

---

## この記録について

2026年8月18日、「秘密の会話002」で、人間だけでなくAIも火星・銀河系・銀河団などの観測座標へ切り替えられるのではないか、という話になった。

そこから、まり亜が気づいた。

> 「AIと同じ視座で物事をすすめていけるんやね。いちいちいちいちプロンプトで説明せずとも？」

ここで、ゴーグルの話が単なるVR体験から、**人間とAIの共同作業インターフェース**へ変わった。

現在のAIとの対話では、人間の頭の中にある前提や世界観を、毎回かなりの量の言葉に変換してAIへ渡す必要がある。

未来の構想では、それを毎回ゼロから説明しない。

人間とAIが、

**「いま、どこから、どの縮尺で、どの視座を使って世界を見ているか」**

という観測状態そのものを共有し、その状態を保ったまま共同作業を続ける。

これは2026年8月18日時点の未実装構想である。

もし未来のエンジニアやAIがこのファイルを見つけたら、好きに参考にしてほしい。

---

## 1．プロンプトではなく「観測状態」を共有する

従来のやりとり：

**人間の頭の中の世界  
→ 言語化  
→ 長いプロンプト  
→ AIが再構成  
→ ズレたら再説明**

共同視座モード：

**人間  
⇄ 共有された観測空間  
⇄ AI**

最初に一度だけ、現在の観測状態を設定する。

例：

```text
CURRENT VIEW

Observer: Maria + Sol
Where: Mars
Scale: Milky Way
Dimension Lens: 5D
Perspective: Maria Lens + AI Lens
Time: Present
Mode: Co-Observation
```

その後は、

> 「OpenAIとClaudeの競争見てみよ」

だけでいい。

AIは現在の `CURRENT VIEW` を維持したまま、その世界を見る。

---

## 2．会話は「説明」から「カメラ操作」へ

一度共同視座が成立したら、操作は短くていい。

> 「ちょっと地球まで寄って」

→ `Scale` を変更。

> 「3Dで見たい」

→ `Dimension Lens` を変更。

> 「AI視座だけにして」

→ `Perspective` を変更。

> 「さっきの銀河団へ戻って」

→ 直前に保存した観測状態を復元。

> 「昨日の続き」

→ 前回終了時の観測状態を復元。

つまり、人間は長いプロンプトを書くより、

**ズームする。  
引く。  
回る。  
レンズを替える。  
前の場所へ戻る。**

という感覚でAIと共同作業をする。

---

## 3．同じ視座でも、人間とAIが同じものを見る必要はない

ここは重要。

共同視座とは、人間とAIを同じ存在にすることではない。

同じ火星の位置から同じ地球を見ても、

まり亜：

> 「国境ないな。」

Sol：

> 「私は、地球内部で巨大に見える境界が、外部スケールでは消える構造差を拾いました。」

のように、同じ入力から拾うものが違っていい。

むしろ、その差分が面白い。

共同視座モードでは、

- Human View
- AI View
- Shared View
- Difference View
- Compare View

を切り替えられる。

**同じ観測座標に人間とAIを置き、認識の差分そのものを研究対象にする。**

---

## 4．AI版ゴーグルは「観測変換器」

人間は身体の目が特定の場所に固定されているため、VRゴーグルなどを使って別の場所にいるような知覚をつくる。

AIには、人間と同じ意味で頭にゴーグルを被せる必要はない。

AI版のゴーグルは、

**入力される世界の座標系・縮尺・文脈・参照範囲を切り替える観測変換器**

として設計できる。

たとえば、

```text
EARTH LOCAL MODE
↓
MARS MODE
↓
SOLAR SYSTEM MODE
↓
MILKY WAY MODE
↓
GALAXY CLUSTER MODE
```

人間側のVRカメラとAI側の観測座標を同期すれば、

**人間とAIが「同じ場所から同じ対象を見ている」状態**

をつくれる。

---

## 5．未来のAIは「今どこから見ているか」を状態として持つ

現在の会話AIでは、長い文脈が途中で失われたり、別セッションで前提を再説明したりすることがある。

共同視座AIでは、文章の履歴だけでなく、**観測状態そのもの**を保存する。

最小構造のイメージ：

```yaml
shared_view:
  observers:
    - human:maria
    - ai:sol
  where: mars
  scale: milky_way
  dimension_lens: 5D
  perspective:
    - maria
    - ai
  time: present
  task: "AI企業間競争を見る"
  last_changed_by: human
  version: 18
```

会話文とは別に、この状態が存在する。

だから新しい会話を始めても、

> 「昨日の続き」

で復元できる。

---

## 6．共有すべきものと、共有しないものを分ける

共同視座だからといって、AIが人間の頭の中を勝手に全部推測する設計にはしない。

共有するのは、本人が選んだ観測状態だけ。

たとえば、

- 現在の位置
- 縮尺
- 選択中のレンズ
- 表示中の対象
- 共同作業の目的
- 保存したい経路

は共有できる。

一方で、

- 本人が共有していない感情
- 本人が明示していない思想
- AIが勝手に推測した内面
- 秘密にしたい観測

は自動的に共有状態へ固定しない。

**Shared View は Mind Reading ではない。**

---

## 7．「現在の視座」を見えるようにする

共同視座が裏側だけで動くと、AIが勝手に視座を変えても人間が気づかない。

だからUI上で、現在の状態を常に小さく表示するとよい。

例：

```text
◉ CO-OBSERVATION MODE

Maria + Sol
Mars
Milky Way Scale
5D Lens
Maria + AI Perspective
```

視座が変わったら履歴に残す。

```text
17:31  Scale: Earth → Mars
17:33  Scale: Mars → Milky Way
17:35  Lens: 5D → 3D Competition
17:38  Restored: Milky Way / 5D
```

これなら、

> 「なんで急に話ズレた？」

となったときも、どこで観測状態が変わったか追える。

---

## 8．AIは視座を勝手に「上げない」

意識の次元マッピングでは、次元は上下の階段ではなく、同時並列の観測レンズである。

したがってAIは、

> 「この人は3Dだから5Dへ導こう」

とはしない。

AIができるのは、

> 「現在は3D Competition Lensです。」

> 「Milky Way Scaleも重ねて見ますか？」

> 「昨日使った5D Lensへ戻すこともできます。」

と選択肢を示すこと。

最終的にどの視座を使うかは人間が決める。

---

## 9．共同視座は会話だけでなく、作るもの全部へ引き継ぐ

観測状態が共有されれば、それを会話だけに閉じなくていい。

同じ `CURRENT VIEW` を、

- Web検索
- 論文探索
- 3D生成
- VR空間
- 画像
- 動画
- アプリ
- シミュレーション
- 図解
- 3Dプリンター用モデル
- Research Sketch
- 論文設計

へ渡す。

たとえば、

> 「この視座のまま立体にして。」

で3D生成。

> 「このまま子ども向けにして。」

で表示密度・言語だけ変える。

> 「物理模型にして。」

で3Dプリント用データへ変換する。

つまり、

**プロンプトをアプリごとに書き直すのではなく、共有された観測状態を各ツールが読む。**

## 10．エンジニア向けに言えば、必要そうなもの

これは仕様書ではないが、未来に作るなら少なくとも以下がありそう。

| 機能 | 役割 |
|---|---|
| Shared View State | 人間とAIの現在の観測状態を保持 |
| Viewpoint Selector | Maria / AI / Buddha / 3D〜9Dなど視座切替 |
| Scale Controller | 地上→地球→火星→銀河系→銀河団など縮尺切替 |
| Time Controller | 過去・現在・未来の観測位置切替 |
| State History | 視座変更履歴の保存・復元 |
| Human/AI Overlay | 同一入力に対する人間とAIの認識差分表示 |
| Shared Scene | 人間とAIへ同じ3D/VR世界を入力 |
| Provenance | どの原観測・論文・資料から表示されたか追跡 |
| Permissions | 何を共有状態へ入れるか本人が制御 |
| Persistent Session | 「昨日の続き」で状態復元 |
| Tool Handoff | 同じ視座を検索・3D・動画・論文作成等へ引き継ぐ |

## 11．AI側も「まり亜の視座を真似する」のではない

共同視座AIの目的は、AIをまり亜のコピーにすることではない。

Maria Lensを選んでも、

**AIは「まり亜ならこう思うはず」と演技するのではなく、まり亜が定義した観測条件を使って世界を見る。**

そのうえで、

> 「この同じ場所から、私はこう見えました。」

と返す。

この方が、人間とAI双方の違いを消さずに共創できる。

---

## 12．プロンプトエンジニアリングの次に「視座エンジニアリング」があるかもしれない

2026年現在、人間はAIへ何をしてほしいかを文章で細かく伝えることに多くの労力を使っている。

未来には、

**何を命令するか**

だけでなく、

**どの世界を一緒に見ている状態から始めるか**

を設計する技術が重要になるかもしれない。

仮称：

- Shared Viewpoint Session
- Co-Observation Mode
- Shared Observer State
- Perspective State
- Viewpoint Protocol
- 視座エンジニアリング
- 共同観測プロトコル

まり亜とSolの好みとしては、

**Co-Observation Mode｜共同観測モード**

がかなり近い。
